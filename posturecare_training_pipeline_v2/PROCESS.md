# AI 학습 프로세스 (PostureCare 64채널 모델)

전체 흐름은 5단계예요. 지금은 1~3단계가 다 코드로 준비되어 있어서, 명령어만
순서대로 실행하면 됩니다.

## 0. 폴더 구조

```
posturecare_training/
├── ml/
│   ├── load_dummy.py              ← 더미 데이터 로더 (팀원 클로드 작성)
│   ├── model.py                    ← PostureCNN64 모델 정의
│   ├── train_dummy.py              ← 학습 스크립트 (더미/실측 공용)
│   └── make_windows_from_real.py   ← 실측 CSV -> 64채널 윈도우 변환기
├── data/
│   ├── dummy/dummy_windows.npz     ← 더미 데이터(팀원분한테 받은 것)
│   ├── raw/*.csv                   ← 실측 CSV (지금은 aro 7개만 예시로 들어있음)
│   └── real/real_windows.npz       ← raw를 변환기로 만든 실측 윈도우
└── runs/
    ├── dummy_v1/                   ← 더미 데이터 학습 결과 (파이프라인 점검용)
    └── real_v1/                    ← 지금 있는 실측 7개로 학습해본 결과 (아직 1명뿐이라 참고용)
```

## 1단계 — 파이프라인 점검 (더미 데이터, 이미 완료)

```bash
python3 -m ml.train_dummy --data data/dummy/dummy_windows.npz --epochs 15 --out runs/dummy_v1
```

검증 정확도 1.000이 나오는데, 이건 라벨이 합격 기준 규칙으로 만들어졌기 때문이고
모델 성능이 아니에요. **"코드가 끝까지 에러 없이 돈다"**를 확인하는 단계예요.
✅ 완료.

## 2단계 — 실측 데이터를 학습 가능한 형태로 변환

지금 `data/raw/`에 실측 CSV가 쌓이는 대로(자세 데이터 수집 매뉴얼대로 수집한
파일들), 이 변환기로 더미와 같은 포맷의 npz로 만들어요.

```bash
python3 -m ml.make_windows_from_real --raw-dir data/raw --out data/real/real_windows.npz
```

- 실측 CSV는 지금 방석 32채널만 있어서(등받이 센서 미도착), 등받이 32채널은
  `synth_back()`이 server_64ch.py의 임시 8x4 격자 규칙으로 자동 합성해요.
  더미데이터와 똑같은 가정이라 나중에 두 데이터셋을 섞어도 일관돼요.
- 실측 fps가 50으로 고정이 아니라 흔들려서(관측상 50~58fps), timestamp 기준
  100ms 구간 평균으로 10Hz 리샘플해요 (더 정확함).
- ⚠️ 등받이 실측 센서 도착하면 `synth_back()` 호출부만 실측 컬럼 읽기로
  바꾸면 나머지 로직은 그대로 재사용돼요.

지금 갖고 있는 실측 7개(아로, 1인분)로 돌려보면 182개 윈도우가 나와요 — 아직
1명뿐이라 이걸로 "진짜 성능"을 말하긴 일러요. 그래도 파이프라인 자체는 정상
동작 확인했어요 (아래 3단계 결과 참고).

## 3단계 — 학습 (같은 스크립트, 데이터만 바꿔서)

```bash
python3 -m ml.train_dummy --data data/real/real_windows.npz --epochs 10 --out runs/real_v1
```

지금 있는 실측 7개로 돌려보면 검증 정확도 0.806이 나와요(더미의 1.000과 달리
현실적인 숫자죠). 다만 참가자가 1명뿐이라 "사람 단위로 검증"이 불가능해서,
스크립트가 자동으로 "윈도우 단위 무작위 분할"로 대체하고 그 사실을 경고로
출력해요. 참가자가 늘어나면(섭외 케이스 매트릭스 채워지는 대로) 자동으로
사람 단위 분할로 바뀌고, 그때부터 나오는 숫자를 신뢰할 수 있어요.

**핵심: 앞으로 다혜님이 할 일은 실측 CSV가 늘어날 때마다 2단계 → 3단계
두 명령어만 다시 실행하는 것**뿐이에요. 코드는 안 바꿔도 돼요.

## 4단계 — 결과 확인하고 부족한 부분 보강

`runs/<이름>/` 안의 `val_report.txt`(클래스별 precision/recall)와
`confusion_matrix.png`를 보고, 어떤 자세가 잘 안 맞는지 확인해요. 예를 들어
지금 실측 7개 결과에서 `cross_leg_left`가 0점인 건, 학습 데이터가 너무
적어서(파일당 26개 윈도우, 그마저 1명분) 생기는 일반적인 현상이에요 —
데이터가 부족하다는 신호로 보고 해당 자세/케이스의 실측을 더 모으면 돼요.

## 5단계 — 실측이 충분히 쌓이면 (앞으로)

- 여러 참가자(섭외 케이스 F1~F9/M1~M9)의 실측이 쌓이면 `data/raw/`에 계속
  추가하고 2~3단계 반복.
- 등받이 실측 센서가 도착하면 `make_windows_from_real.py`의 `synth_back()`
  호출을 실측 back 컬럼 읽기로 교체.
- 만족스러운 정확도가 나오면, 기존에 해두신 것처럼 PyTorch → TFLite 변환해서
  서버/앱에 배포.

## 자주 헷갈릴 수 있는 것

- **더미데이터 학습 결과(1.000)** = 코드가 도는지 확인용, 성능 아님.
- **지금 실측 7개 학습 결과(0.806)** = 참고용, 1명분이라 아직 일반화 여부를
  말할 수 없음.
- **의미 있는 성능 숫자**는 여러 참가자의 실측이 쌓이고 "사람 단위 분할"이
  제대로 된 다음부터예요.
