## 지금 상태 요약

- **자세 7종** (p0~p6, 앱 `posture_class.dart` 의 `canonical` 7개와 같은 순서). **거북목은 뺐습니다.**

  | 코드 | 자세 | 코드 | 자세 |
  |---|---|---|---|
  | p0 | 앉지 않음 | p4 | 왼다리 꼬기 |
  | p1 | 정자세 | p5 | 오른쪽 기대기 |
  | p2 | 앞으로 숙이기 | p6 | 왼쪽 기대기 |
  | p3 | 오른다리 꼬기 | | |

- **모델**: 부스팅(HistGradientBoosting) 2개 — 모양 모델 + 캘리브레이션 차이 모델 — 의 확률 평균.
  **판정 규칙(덮어쓰기) 없음.** 나무들을 행렬 계산으로 옮겨 TFLite로 변환했고, 원래 모델과 예측 일치율 100%.
- **입력** `[1, 128]` float32 원시값 = 지금 프레임 ch0~63 + **캘리브레이션 기준값** ch0~63
  (정자세 5초 평균). 정규화하지 않고 그대로 넣습니다. **출력** `[1, 7]` 자세별 확률.
- **학습 데이터**: 실측 4명(아로·다혜·준서·예원) 중 자세 정의에 맞는 녹화 + 정의대로 만든 더미 + 좌우 반전.
  거북목 데이터는 실측·더미 모두 삭제했습니다.
- **정확도** (사람 단위 LOPO = 처음 보는 사람으로 테스트, 실측만)

  | 자세 | 정의에 맞는 녹화 | 전체 녹화 |
  |---|---|---|
  | 앉지 않음 | 99.9% | 99.9% |
  | 정자세 | 99.9% | 76.5% |
  | 앞으로 숙이기 | 97.5% | 97.5% |
  | 오른다리 꼬기 | 95.5% | 95.5% |
  | 왼다리 꼬기 | 99.2% | 99.2% |
  | 오른쪽 기대기 | 96.8% | 77.3% |
  | 왼쪽 기대기 | 98.6% | 73.9% |
  | **합산** | **98.0%** | **88.3%** |

  - "전체 녹화"는 정의와 다르게 찍힌 녹화(어깨가 안 닿은 정자세·기대기 등)까지 포함한 숫자입니다.

## 앱에 붙일 때 (예원)

| 항목 | 값 |
|---|---|
| 모델 파일 | `ml/posture_model_gbt.tflite` → `assets/model/` 로 복사 |
| json | `ml/norm_stats_gbt.json` (`label_order` 7개 = 앱 `kExpectedLabelOrder` 와 같음, `model_io.input_shape` = [1,128]) |
| 입력 | 지금 프레임 원시값 64개(좌석 ch0~31 + 등받이 ch32~63) 뒤에 캘리브레이션 기준값 64개를 붙인 128개. **정규화 안 함** |
| 출력 | 7개 확률, argmax = `label_order` 인덱스 (= `PostureClass.id` 0~6) |
| 캘리브레이션 | 사용자가 정자세(허리·등·**어깨까지** 등받이에 붙임)로 5초 앉는 동안의 채널별 평균 64개를 저장. 사용자·의자 위치가 바뀌면 다시 잼 |
| 판정 규칙 | 없음 (앱에서 따로 처리할 것 없음) |

자세 종류·순서는 지금 앱과 같아서 `posture_class.dart` 는 바꿀 필요 없습니다(거북목 추가 불필요).
지금 앱(`PosturePreprocessor`)은 입력이 `[1,64,1]` 정규화 값이라, **입력을 위 형식으로 바꾸는 작업**과 캘리브레이션 값 저장이 필요합니다.

## 자주 겪는 문제

### 1. 한글이 깨지거나 `UnicodeEncodeError` (✅ 출력할 때)
터미널에 `$env:PYTHONIOENCODING="utf-8"` 을 먼저 실행합니다.

### 2. `No module named 'tensorflow'` / `'sklearn'`
```
pip install tensorflow scikit-learn
```
학습(TFLite 변환)까지 하려면 `onnx`, `onnx2tf` 도 필요합니다: `pip install onnx onnx2tf`

### 3. 데모에서 `조건에 맞는 녹화가 없습니다`
`--person` / `--posture` 철자를 확인합니다. 자세 이름은 영어(`sitting_straight`, `cross_leg_right` ...), 사람은 날짜를 뗀 이름(`aro`, `dahye`). 거북목(`turtle_neck`)은 모델에서 빠져서 데모에도 안 나옵니다.

### 4. 정자세가 기대기 등으로 나올 때
- 정자세 녹화나 캘리브레이션을 **어깨를 안 붙이고** 하면 정의(어깨 양쪽 100 이상)와 달라집니다 → 어깨까지 붙이고 다시.
- 전체 녹화 기준 정자세 76.5% 는 이렇게 찍힌 예전 녹화(아로 옛 회차, 예원 1번)가 포함된 숫자입니다.

### 5. 학습할 때마다 숫자가 조금씩 다를 때
더미를 다시 만들었거나(`gen_dummy_spec.py`) 실측 파일이 바뀌면 숫자가 달라집니다. 같은 데이터로는 같은 결과가 나옵니다 (시드 고정).

## 남은 이슈 (참고)

- **다혜 앉지 않음** 미측정.
- **어깨를 붙인 정자세·기대기 추가 측정** — 전체 녹화 기준 정자세 76.5%, 기대기 74~77% 는 어깨가 안 닿게 찍힌 녹화 때문. 정의대로 찍은 녹화가 늘면 올라감.
- **서버(`server_64ch.py`)는 아직 예전 CNN 모델** — 새 모델(입력 128, 캘리브레이션 필요)로 바꾸려면 서버의 판정 부분과 캘리브레이션 API 를 고쳐야 합니다. 앱이 온디바이스(TFLite)로 판정한다면 서버는 기록·리포트만 맡아도 됩니다.
- **앱 반입** — 입력 [1,128] 원시값, 캘리브레이션 저장 (표의 8번).
- **등받이 ch48·59·60 좌우 위치** — 반응이 약해서 추정값. 탭 테스트로 확정 필요 (표의 3번).
- **거북목** — 2026-10-25 에 모델·실측·더미에서 모두 뺌. 다시 넣으려면 `ml/train_posture_gbt.py` 의 `DROP` 과
  `gen_dummy_spec.py` 의 `EXCLUDE` 를 비우고, 정의대로 찍은 거북목 녹화(어깨 ch56~63 각 20 이하, 등 400 이상,
  양쪽 무릎 닿음)를 여러 명 모은 뒤 더미 생성 → 재학습. (지운 거북목 CSV 는 git 기록에서 되살릴 수 있음)
