# PostureCare 자세 데이터 수집 매뉴얼 v3

개정 2026-08-16 · 예원
대상: 팀원 누구나 (측정 진행자용)

v1과 달라진 점: **매트·보드 교체**에 따라 포트가 바뀌었고, 수집 전
**좌표계 검증 절차(4절)** 가 추가되었습니다. 합격 기준 수치는 교체 전
예원·아로·다혜 3명 실측에서 나온 값이며, 새 매트에서도 유효한지는
4절 검증으로 확인합니다.

v3에서 달라진 점 (2026-10-15): **등받이 매트가 추가**되어 좌석+등받이
**64ch 동시 수집**을 합니다. 기존 32ch(좌석만) 내용은 그대로 두고, 등받이
항목을 각 절에 **'등받이 (64ch)'** 로 덧붙였습니다. 등받이 합격 기준은
1인 1회 실측(2026-10-15) 또는 근거 없이 정한 **잠정** 값이며, 실제 수집하면서
조정합니다.

## 0. 왜 이렇게까지 하나

같은 자세라도 **앉는 위치가 5cm만 달라져도 센서 9개가 통째로 죽습니다.**
첫 측정에서 왼쪽으로 치우쳐 앉아 오른쪽 채널이 전부 0으로 나왔고,
눈으로는 전혀 티가 나지 않았습니다.

수집이 끝난 뒤에 발견하면 그 사람을 다시 불러야 합니다.
**자세 하나가 끝날 때마다 그 자리에서 결과를 확인하세요.**

## 2. 보드 준비 (새 보드일 때만)

새 보드는 펌웨어가 비어 있어 **빨간 LED만 켜집니다.** 업로드가 필요합니다.

### 2-1. Arduino IDE Tools 설정 — ★ 5개 필수

| 항목 | 값 |
|---|---|
| Board | ESP32S3 Dev Module |
| Port | 아래 3절에서 확인한 값 |
| **USB CDC On Boot** | **Disabled** ★ Enabled면 데이터가 안 나옵니다 |
| Flash Mode | QIO 80MHz |
| Flash Size | 16MB (128Mb) |
| **Partition Scheme** | **Custom** ★ |
| PSRAM | OPI PSRAM |
| Upload Speed | 921600 |

필요 라이브러리: `Adafruit NeoPixel`, `NimBLE-Arduino 2.5.1`

### 2-2. 업로드와 확인

`firmware/PoseLabCore_BLE/` 의 `.ino` 를 열고 `Cmd + U`.

정상 신호 2가지:

| 확인 | 정상 |
|---|---|
| LED | 무지개(빨강→초록→파랑→노랑→청록→자홍→흰색) 후 **앰버(주황빛 노랑) 고정** |
| Serial Monitor (baud **2000000**) | `==== PoseLab Core ====` 배너 후 CSV가 빠르게 흐름 |

★ 배너는 부팅 때 한 번만 나옵니다. Serial Monitor를 나중에 열었으면
보드 RST 버튼을 누르거나 USB를 다시 꽂으세요.

★ **빨강에서 멈춰 있으면** 펌웨어가 안 도는 상태입니다. 업로드부터 하세요.

### 2-3. 등받이 (64ch) — 좌석/등받이 보드 구분

두 보드에 **같은 펌웨어**를 그대로 올리고, 보드 위 **DIP 스위치 SW1** 로 역할을 정합니다.

| 보드 | SW1 | BLE 이름 | 배너 확인 |
|---|---|---|---|
| 좌석 | **OFF** | `PoseLab-Seat` | `Role       : SEAT (PoseLab-Seat) via DIP SW1` |
| 등받이 | **ON** | `PoseLab-Back` | `Role       : BACK (PoseLab-Back) via DIP SW1` |

★ SW1 은 **부팅할 때만** 읽습니다. 스위치를 바꿨으면 RST 버튼을 누르세요.

★ 배너에 `SW1=OFF` 로만 나오면(스위치 없음·불량) `.ino` 의
`// #define BOARD_ROLE_FORCE_BACK` 주석을 풀고 **등받이 보드에만** 올린 뒤,
주석을 원래대로 되돌려 두세요.

## 4. ★ 좌표계 검증 (매트를 교체했으면 반드시)

새 매트는 배선이 이전과 같다는 보장이 없습니다. 좌표계가 다르면
기존 데이터와 섞을 수 없으므로 **수집 전에 확인**합니다.

### 기준 좌표계 (교체 전 실측 확정값)

| 채널 | 부위 |
|---|---|
| 0~4 | 오른쪽 엉덩이 (ch0이 몸 바깥) |
| 5~9 | 왼쪽 엉덩이 |
| 10~16 | 오른쪽 허벅지 |
| 17~23 | 왼쪽 허벅지 |
| 24~27 | 오른쪽 무릎 |
| 28~31 | 왼쪽 무릎 |

★ 물리적으로는 **가로 3열 배선**입니다 — 하단 10칸(0~9) / 중단 14칸(10~23) /
상단 8칸(24~31). 좌우 반전 순열이 "각 열을 통째로 뒤집기"와 일치하는 것으로
확인되었습니다 (cross_leg 좌우 코사인 0.978).

### 검증 방법 — 구역별로 하나씩

한 구역만 10초간 손바닥으로 꾹 누르고, 어느 채널이 반응하는지 봅니다.

```bash
python3 ml/collect_data.py --person test --posture zone_a --trial 1 --duration 10 --port /dev/cu.usbmodem5C843561931
```

`--posture` 이름을 `zone_a`, `zone_b` … 로 바꿔가며 구역별로 반복합니다.

| 누를 곳 | 기대 채널 |
|---|---|
| 엉덩이 줄 한쪽 끝 | ch0~4 |
| 엉덩이 줄 반대쪽 | ch5~9 |
| 가운데 줄 전체 | ch10~23 |
| 위 줄 전체 | ch24~31 |

★ 기대와 다르게 나오면 **수집을 시작하지 말고** 매핑을 다시 정리해야 합니다.
`lib/models/sensor_layout.dart` 와 `ml/augment_data.py` 의 구역 정의를
함께 고쳐야 하므로 혼자 판단하지 마세요.

★ 전수 검증 한 번으로 끝내려 하지 마세요. 32칸을 30초 안에 정확히 다
짚기 어려워서, 안 눌린 채널이 죽은 것처럼 보입니다. 구역별로 나눠야
확실합니다.

### 등받이 (64ch) 좌표계

등받이 매트도 좌석과 같은 **10 / 14 / 8 구조**입니다. 64ch 파일에서는 등받이가
ch32~63 에 들어갑니다 (등받이 보드의 ch0 → ch32).

| 채널 | 부위 | 근거 |
|---|---|---|
| 32~36 | 왼쪽 허리 | 오른쪽 허리(37~41)의 나머지 |
| 37~41 | 오른쪽 허리 | **실측** |
| 42~48 | 왼쪽 중간 | 추정 |
| 49~55 | 오른쪽 중간 | 추정 — 오른 허리를 눌렀을 때 ch50·52~55 가 함께 켜짐(2026-10-15) |
| 56~59 | 왼쪽 어깨 | 56~58 **실측**, 59 추정 |
| 60~63 | 오른쪽 어깨 | 61~63 **실측**, 60 추정 |

> ★★ **등받이는 좌석과 좌우가 반대입니다.**
> 좌석은 번호가 **작을수록** 사용자의 오른쪽(ch0~4 = 오른 엉덩이),
> 등받이는 번호가 **클수록** 사용자의 오른쪽(ch61~63 = 오른 어깨)입니다.
> 매트를 세워서 달았기 때문입니다. 기준표를 볼 때 좌석 감각으로 읽지 마세요.

검증 방법은 좌석과 같습니다. 등받이 한 구역만 손바닥으로 누르고 64ch 로 받습니다.

```bash
python3 ml/collect_data.py --person test --posture zb_a --trial 1 --duration 10 --port /dev/cu.usbmodem5C843561931 --port-back /dev/cu.usbmodem5C843561121
```

| 누를 곳 (사용자 기준) | 기대 채널 | 2026-10-15 실측 |
|---|---|---|
| 오른쪽 허리 | ch37~41 | 37~41 + 중간 줄 50·52~55 (손바닥이 중간 줄까지 걸침) |
| 왼쪽 어깨 | ch56~59 | 56·57·58 |
| 오른쪽 어깨 | ch60~63 | 61·62·63 (+ 51·55) |

★ 아직 확인 안 된 칸: **중간 줄 좌우 경계(48|49), ch59, ch60.** 다음 검증 때
중간 줄 양 끝과 어깨 줄 가운데를 따로 눌러 확정하세요.

## 5. 환경 세팅 — 한 번 정해서 끝까지 고정

★ 이 세팅이 사람마다 달라지면 데이터를 비교할 수 없게 됩니다.

| 항목 | 방법 |
|---|---|
| 방석 중앙선 | 매트 좌우 정중앙에 테이프를 세로로 붙인다 |
| 방석 위치 | 의자 위 놓는 자리를 테이프로 표시 |
| 의자 위치 | 바닥에 의자 다리 위치를 테이프로 표시 |
| 케이블 | 보드가 움직이지 않게 고정 (매트가 밀리면 좌표계가 어긋남) |
| Arduino IDE | Serial Monitor 창은 **반드시 닫을 것** (포트를 하나만 열 수 있음) |
| 앱 | BLE 앱도 끄는 편이 안전 |

등받이 (64ch) 추가 세팅

| 항목 | 방법 |
|---|---|
| ★ **등받이 매트 높이** | 매트 아래 끝과 좌석면 사이 간격을 재서 **테이프로 표시하고 cm 를 메모**. 사람마다 높이가 달라지면 어깨·허리 채널이 어긋나 데이터를 합칠 수 없습니다 |
| 등받이 중앙선 | 등받이 매트 좌우 정중앙에 세로 테이프. **좌석 중앙선과 일직선**이 되게 |
| 등받이 고정 | 네 모서리를 테이프로 고정 (기대면 매트가 아래로 밀립니다) |
| 등받이 보드 케이블 | 좌석 보드와 따로 고정. 두 케이블이 엉켜 당겨지지 않게 |

★ FFC 커넥터를 반복해서 뺐다 꽂으면 **접촉이 나빠집니다.** 이전 매트가
그렇게 망가졌습니다. 값이 안 나와도 커넥터를 계속 만지지 마세요.

## 8. 진행 순서

```
1. 자세를 먼저 잡는다  ★ 명령 실행 전에
2. 진행자가 눈으로 자세를 확인한다
3. 명령 실행 (3초 카운트다운이 있음)
4. 30초 동안 유지 — 말 걸지 말 것
5. ★ 결과 요약을 그 자리에서 확인한다
6. 기준 미달이면 즉시 재촬영
7. 다음 자세로 넘어가기 전에 한 번 일어났다 앉기
```

★ 3초 카운트다운은 **자세 미세조정용**이지 앉는 시간이 아닙니다.
앉기 전에 실행하면 빈 프레임만 쌓입니다 (실제로 2회 발생).

★ 7번이 중요합니다. 매번 다시 앉으면 미세한 위치 차이가 생기는데,
그 변화가 오히려 모델을 튼튼하게 만듭니다.

★ 앉은 사람이 직접 명령을 치기 어려우므로, **한 명은 앉고 한 명은 노트북**을
맡는 2인 1조가 편합니다.

## 9. 자세별 지시문과 합격 기준

지시문은 **그대로 읽어주세요.** "정자세로 앉으세요"라고만 하면 사람마다 다르게 앉습니다.

★ 64ch 로 수집할 때는 각 자세 아래 **'등받이 (64ch)'** 기준도 함께 봅니다.
등받이 수치는 전부 **잠정**입니다 (1인 1회 실측이거나 근거 없이 정한 값).

## 10. 결과 화면 읽는 법

```
전 채널 0 프레임: 0 (0.0%)          ← 앉은 자세인데 높으면 이상

[좌우 균형]  좌 51.1%  /  우 48.9%   ← 자세별 기준표 참고
[앞뒤 분포]  엉덩이 29.2% / 허벅지 47.3% / 무릎 23.4%

⚠️ 한 번도 값이 안 잡힌 채널 1개: [0]   ← 아래 설명 참고
```

**죽은 채널 경고를 만났을 때**

| 상황 | 판단 |
|---|---|
| 1~3개, 매트 가장자리 | 정상. 그 사람 체형상 안 닿는 자리 |
| 좌우 한쪽으로 몰림 | 치우쳐 앉음. **재촬영** |
| 다리꼬기에서 한쪽 무릎 4개 | 정상. 오히려 이게 목표 |
| 앉았는데 32개 전부 | 배선 문제. 11절 참조 |

★ 예원은 ch00, 아로는 ch27·ch31이 늘 비었습니다. 사람마다 안 닿는 자리가
다른 것은 정상이고, 오히려 체형 차이라서 학습에 도움이 됩니다.

★ **`lean_` 과 `cross_leg_` 로 시작하는 자세는 좌우 경고가 면제**됩니다
(불균형이 정상이므로). 수치만 표시되니 기준표와 직접 대조하세요.

### 10-1. 등받이 (64ch) 결과 읽는 법

64ch 로 받으면 위 내용에 아래가 더 나옵니다. (프레임 수·fps 는 형식 설명용 예시)

```
[보드별 수신]
  좌석   :  1498 프레임 ( 49.9 fps)  파싱 실패 1
  등받이 :  1497 프레임 ( 49.9 fps)  파싱 실패 1
  저장 행:  1495 행     ( 49.8 fps)  버린 행(등받이 100ms 초과) 3 (0.2%)

[좌석 : 등받이 압력]  좌석 59.9%  /  등받이 40.1%   ← 자세별 기준표 참고
등받이 전 채널 0 행: 0 (0.0%)  (등을 안 댄 시간 비율)

[등받이 채널별 평균 / 최대]   ← ch32~63, 죽은 채널 표시
```

| 줄 | 읽는 법 |
|---|---|
| 보드별 fps | 두 보드 모두 50 근처여야 합니다. 한쪽만 낮으면 그 보드 케이블 확인 |
| 버린 행 | 등받이 값이 100ms 넘게 안 온 행은 **0 으로 채우지 않고 버립니다** (등받이 0 은 '등을 안 댐'이라는 진짜 신호라 끊김과 섞이면 안 됨). **5% 넘으면 재촬영** |
| 500ms 넘는 끊김 경고 | 케이블이 흔들렸거나 빠진 것. **재촬영** |
| 좌석 : 등받이 압력 | 자세별 기준표와 대조 |
| ⚠️ 포트가 바뀌었을 수 있음 | 등받이 압력이 좌석보다 큼. 앉은 자세에서 뜨면 `--port` / `--port-back` 을 바꿔 넣은 것 |
| 등받이 전 채널 0 행 | 등을 안 댄 시간 비율. lean_forward·not_sitting 은 높아야, 나머지는 낮아야 정상 |

★ '전 채널 0 프레임'과 '좌우 균형', '앞뒤 분포'는 64ch 에서도 **좌석 ch0~31 기준**입니다.

## 11. 값이 안 나올 때

| 증상 | 판단 |
|---|---|
| 포트가 안 잡힘 | 케이블 확인. 충전 전용이면 안 잡힘 |
| 포트는 잡히고 프레임도 오는데 **값만 0** | ★ 매트-보드 접촉 불량 |
| **잴 때마다 살아나는 채널이 바뀜** | ★ 죽은 셀이 아니라 접촉 불량 확정 |
| 전 채널 최대값이 20~45 | 노이즈 수준. 압력이 전혀 안 잡히는 상태 |
| LED 빨강에서 멈춤 | 펌웨어 미업로드 (2절) |

★ **LED가 켜진다 = 정상이 아닙니다.** 전원(VBUS)만 살아도 켜집니다.

★ 접촉 불량이 의심되면 FFC 커넥터를 **한 번만** 확인하고, 그래도 안 되면
멈추세요. 반복해서 만지면 악화됩니다. 이전 매트가 그렇게 망가졌습니다.

지원: `support@poselab.app`

## 13. 자주 겪는 문제

|---|---|
